# Visual Product Similarity & Image-Based Recommendation System

## Overview
Amazon-style visual recommendation system that finds visually similar products using only
product images - upload a photo, get back the most visually similar items in the catalog.

## A note on the dataset

The 58 product images shipped in `data/raw_images/` are real JPEGs, but the catalog itself
is thin: checksumming them shows only **12 visually distinct images**, with two of those
repeated ~20 times each under different filenames. The original metadata even assigned
different product names (a shirt, a pair of sneakers, jeans) to byte-identical photos - so
this was clearly built as a placeholder/demo set, not real product photography.

That means the Precision@K numbers below are real (the pipeline genuinely ran end-to-end
against this data), but they're propped up by exact-duplicate images being trivially "similar
to themselves" rather than by the model generalizing across genuinely different products.
Swap in a real dataset (Stanford Online Products, DeepFashion, or the Amazon Product Images
dataset - 1000+ images, no exact dupes) via `data/raw_images/` + `data/metadata.csv` for
numbers that actually mean something.

## Objective
- Extract high-quality image embeddings using a pretrained CNN
- Build a fast similarity search engine with FAISS
- Retrieve Top-K visually similar products
- Provide an optional Streamlit web app interface

## Tech Stack
- Python, PyTorch
- ResNet50 (final classification layer stripped, 2048-dim pooled features)
- FAISS HNSW index (approximate nearest neighbor, inner product on L2-normalized
  vectors = cosine similarity)
- Streamlit

## Installation
```bash
pip install -r requirements.txt
```

## Run steps
```bash
python src/extract_embeddings.py   # ResNet50 -> models/embeddings.npy (~1-2 min on CPU)
python src/build_index.py          # builds the FAISS HNSW index
python src/evaluate.py             # Precision@K / Recall@K over the catalog
streamlit run src/app.py           # interactive search UI
```

## Results (on the shipped 58-image sample set)

```
Evaluated queries: 58
Average Precision@5: 0.3966
Average Recall@5: 0.0830
```

Given the dataset note above, read this as "the pipeline works and returns sensible,
visually-grounded matches" rather than as a benchmark number - a duplicate image scores a
perfect 1.0000 cosine similarity against its copies, which is exactly what you'd want, but
it's not really testing generalization to unseen products.

## Demo walkthrough
```
$ python src/search.py

1. img98.jpg | Score: 1.0000
2. img93.jpg | Score: 1.0000
3. img88.jpg | Score: 1.0000
4. img83.jpg | Score: 1.0000
5. img8.jpg | Score: 1.0000
```
(img3 has 20 byte-identical copies elsewhere in the sample set, hence the perfect scores -
see the dataset note.)

In the Streamlit app: upload any image from `data/raw_images/`, optionally narrow by
category/price/availability in the sidebar, and the top-K panel fills in with the closest
matches and their metadata.

## Features
- ResNet50 embedding extraction, L2-normalized
- FAISS HNSW approximate nearest-neighbor search
- Cosine similarity ranking
- Filtering by category, price range, and availability
- Streamlit UI for image upload and result display

## Evaluation
- Precision@K, Recall@K (`src/evaluate.py`, category match used as the relevance proxy)
- Visual inspection via the Streamlit results grid

## Notes
- Place product images inside `data/raw_images/`; corrupt/unreadable files are skipped
  with a warning during extraction rather than crashing the whole run
- If metadata is unavailable for an image, the pipeline still works with just the image path
- `models/` and `data/processed/` are regenerated by the scripts, not committed to git
